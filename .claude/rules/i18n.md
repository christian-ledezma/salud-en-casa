# Internacionalización

Se carga al trabajar con recursos de cadenas o con cualquier texto visible.

## Regla

**Ningún texto visible al usuario se escribe en el código.** Sin excepciones.

Aplica a etiquetas, textos de botón, encabezados, mensajes de error, textos de
estado vacío, descripciones de contenido para accesibilidad, títulos y cuerpos de
notificación, opciones de menú, marcadores de posición de campos, unidades y
formatos.

Un texto escrito directamente es un defecto, aunque la aplicación funcione.

## Estructura

```
app/src/main/res/
├── values/strings.xml        Idioma de reserva
├── values-es/strings.xml     Español, idioma inicial
└── values-en/strings.xml     Inglés, fase posterior
```

El idioma inicial del producto es el español. `values/` existe desde el primer día
como reserva, para que agregar un idioma sea traducir un archivo y no recorrer el
código buscando textos.

## Nomenclatura de claves

Claves en inglés, en `snake_case`, con la estructura `<ámbito>_<elemento>_<variante>`.

| Ámbito | Prefijo | Ejemplo |
|---|---|---|
| Común a toda la aplicación | `common_` | `common_continue`, `common_cancel`, `common_retry` |
| Errores | `error_` | `error_network_unavailable`, `error_invalid_phone` |
| Descripciones de accesibilidad | `cd_` | `cd_professional_photo`, `cd_back_button` |
| Por característica | `<feature>_` | `auth_sign_in_with_google`, `request_create_title` |
| Notificaciones | `notification_` | `notification_new_offer_title` |

Ejemplos correctos:

```
auth_sign_in_with_google
auth_role_selection_title
profile_professional_base_rate_label
search_no_professionals_nearby
offer_counter_offer_button
payment_awaiting_professional_confirmation
error_amount_must_be_positive
cd_verified_badge
```

Nunca `text1`, `label_2`, `msg_ok`. La clave debe indicar dónde vive y qué dice.

## Parámetros

Siempre posicionales y explícitos, para que el traductor pueda reordenarlos.

```xml
<string name="search_results_count">%1$d profesionales a menos de %2$d km</string>
```

Nunca concatenar cadenas para formar una frase. El orden de las palabras cambia
entre idiomas y la concatenación lo rompe.

## Plurales

Usar `plurals`, nunca una condición en el código.

```xml
<plurals name="offer_round_count">
    <item quantity="one">%d ronda de negociación</item>
    <item quantity="other">%d rondas de negociación</item>
</plurals>
```

## Formatos que dependen de la configuración regional

No se escriben a mano. Se resuelven con las utilidades de la plataforma o de
`kotlinx-datetime`, tomando la configuración regional del dispositivo.

| Dato | Cómo se formatea |
|---|---|
| Fecha y hora | Formateador de la plataforma con la configuración regional activa |
| Moneda | Formateador de moneda con `BOB`, nunca `"Bs " + monto` |
| Distancia | Recurso con parámetro, con la unidad dentro de la cadena traducible |
| Números | Formateador con separador de miles según la configuración regional |

## Mensajes de error

El dominio no conoce textos. Un caso de uso devuelve un **tipo de error**, no una
frase.

```kotlin
sealed interface RequestError {
    data object PatientHasNoPrimaryAddress : RequestError
    data object ProfessionalNotVerified : RequestError
    data class AmountOutOfRange(val min: Int, val max: Int) : RequestError
}
```

La capa de presentación traduce ese tipo a una clave de recurso. Así la regla de
negocio permanece libre de idioma y el mismo error puede presentarse distinto en
cada pantalla.

**Nunca** devolver `Error("El monto debe ser mayor a cero")` desde un caso de uso.
Esa cadena queda atrapada en la capa de dominio, que no debe conocer los recursos
de Android ni el idioma del usuario.

> Esto reemplaza el uso de `Error(message: String)` que aparece en el proyecto
> previo del autor. El resultado sellado transporta un tipo de error, no un texto.

## Accesibilidad

Toda descripción de contenido proviene de recursos, con el prefijo `cd_`. Los
elementos decorativos declaran la descripción como nula de forma explícita, para
que el lector de pantalla los omita.

## Qué no se traduce

- Identificadores de código, claves y nombres técnicos.
- Valores de tipos enumerados. Un `payment_status` es `BOTH_CONFIRMED` en la base
  de datos; su presentación se traduce en la capa de interfaz mediante una clave
  de recurso.
- Registros de la aplicación. Van en inglés y no son visibles al usuario.
- Los documentos del proyecto.

## Verificación

- Ningún literal de texto visible en archivos de pantalla. El análisis estático
  debe señalarlo.
- Toda clave usada existe en `values-es/` y en `values/`.
- Ninguna clave declarada queda sin usar.
- La aplicación se revisa con el idioma del dispositivo en inglés: no debe
  aparecer ningún texto en español fuera de los recursos.
